CURRENT PROBLEMS TO FIX

1. fixtureplan.rs still uses global periodic placement:
   - wx.rem_euclid(period)
   - wz.rem_euclid(period)
   - fixed 4-unit corridor behavior
   These are not acceptable as primary placement logic.

2. FixtureSample.centerx/centerz are often set to the current query position, not one stable logical panel center.
   This means one panel is not modeled as one entity/rectangle.

3. Corridor fixture placement is not spine-local:
   - It does not derive tangent/normal coordinates from CirculationSpine.
   - It does not derive spacing from corridor width or ceiling height.
   - It does not respond to turns, junctions, thresholds, or corridor direction.
   - composecolumn.rs reconstructs another fixture after calling corridorfixtureat, causing duplicated ownership.

4. Assembly fixture placement does not properly use:
   - CeilingZone polygon containment
   - Structural grid phase and bay dimensions
   - Host walls
   - Openings and thresholds
   - Service voids
   - Structural columns
   - Ceiling language
   It currently behaves mostly like a global repeated grid plus hash filtering.

5. Fabric fixture placement must be derived from fabric-cell geometry:
   - implied walkable area
   - wall/opening topology
   - ceiling band and ceiling height
   - circulation mouth / threshold relation when applicable
   - age and anomaly conditions
   Randomness may select state or bounded variation only AFTER valid candidate geometry exists.

6. Runtime lights have duplicate authority:
   - decideruntimelights currently reads AssemblyInstance.fixtures
   - procedural fixture planning / voxelization is a separate authority
   Create one canonical source of truth.
   Prefer semantic generated fixture layouts or exposed-emissive component extraction, depending on current renderer pipeline constraints.
   Do not create runtime lights independently from legacy authored fixture arrays if equivalent generated fixture semantics exist.

7. Fixture maintenance is underdeveloped:
   - FixtureState exists, but placement and maintenance should be distinct.
   - Dead/failing behavior must cluster spatially by electrical district, room, or corridor segment.
   - Do not use independent per-panel random failures as the primary model.
   - Blackout anomalies override normal conditions.
   - Emergency fixtures should survive selectively where justified.

8. Clean architecture needs enforcement:
   - No renderer/WebGPU/WASM imports in domain or procedural use-case modules.
   - No random mutable RNG consumption whose sequence depends on chunk generation order.
   - No use-case placement logic inside voxelize.rs or renderer adapters.
   - No duplicate fixture-ID algorithms across modules.
   - No duplicated fixture construction in composecolumn.rs after planner output exists.
   - Keep modules cohesive and use private helpers where possible.
   - Prefer immutable data and pure functions.

NON-NEGOTIABLE DESIGN RULE

Randomness may answer:
  “Which valid geometry-derived fixture is degraded, flickering, missing, or dead?”

Randomness must not primarily answer:
  “Where does a fixture exist?”

A fixture must be generated from a valid architectural surface and circulation relationship.

TARGET MODEL

Implement or refine a model like:

Architecture / region / corridor / fabric cell
  -> FixtureLayoutPlan with stable FixtureLayout objects
  -> point query returns Option<FixtureSample>
  -> ColumnPlan stores the sampled fixture reference/data
  -> voxelize turns fixture state into lit/dead/emergency panel materials
  -> baked lighting sees exposed emissive material
  -> runtime-light export derives lights from the same canonical fixture semantics or exposed emissive components
  -> frame preparation only culls/packs/animates lights

Use stable IDs:
- One logical fixture must have one stable ID
- Its ID must not depend on queried voxel position
- Its ID must be independent of chunk partitioning, worker count, call order, renderer, and LOD where semantic identity is preserved
- Use one central stable-ID helper, not separate ad hoc hash code
